## A worked example

```python
import math

def cosine(a: list[float], b: list[float]) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    norm_a = math.sqrt(sum(x * x for x in a))
    norm_b = math.sqrt(sum(y * y for y in b))
    return dot / (norm_a * norm_b)

# 1.0 = identical direction, 0.0 = orthogonal, -1.0 = opposite
print(round(cosine([1, 0, 0], [1, 0, 0]), 2))   # 1.0
print(round(cosine([1, 0, 0], [0, 1, 0]), 2))   # 0.0
```

Cosine similarity ignores magnitude and compares direction, which is why it is the default for text embeddings.

<Callout type="interview" title="Interview corner">
**A 500-word document costs far more tokens than you expect. Why?**

Subword tokenisation splits uncommon words, whitespace, punctuation and even numbers into multiple tokens. Technical prose with identifiers, code and URLs tokenises much worse than ordinary English — often two to four tokens per word. Tokenise your actual corpus and measure rather than estimating from word counts.
</Callout>

## Quick recap

- Tokens are subword units. Count them, do not estimate them.
- Embeddings place related text in nearby directions in high-dimensional space.
- Cosine similarity compares direction, which is what you usually want.
