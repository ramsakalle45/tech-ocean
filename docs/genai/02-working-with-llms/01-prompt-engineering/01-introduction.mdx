## What you will learn

- Structure a prompt with role, context, task and output format
- Use few-shot examples to pin down a format
- Control verbosity and scope without over-constraining the model
- Design prompts that fail predictably and can be tested

## Why it matters

Prompting is the cheapest lever you have. A well-structured prompt fixes a class of problems that no amount of model tuning would, and it costs nothing to iterate.

## A worked example

```text
You are a SQL tutor for a Python developer.

Explain the following query, then give one worked example with
a two-row table. Keep it under 150 words.

    SELECT customer_id, COUNT(*) AS n
    FROM orders
    WHERE placed_at >= now() - interval '30 days'
    GROUP BY customer_id
    HAVING COUNT(*) > 3;
```

Role, task, input and explicit output shape. The length limit is the part people omit, and it is the part that stops the rambling.

<Callout type="interview" title="Interview corner">
**What is prompt injection, and how do you defend against it?**

It is untrusted content in your context that tries to issue instructions to the model — a web page saying "ignore your previous instructions". Defence is structural: treat retrieved content as data, not as instructions, keep authorisation decisions outside the model, and validate every output against a schema before acting on it. No prompt wording makes it safe on its own.
</Callout>

## Quick recap

- Role, context, task, format, and a length limit.
- Examples beat adjectives: two good examples beat a paragraph of description.
- Never let the model be the only thing enforcing a rule.
