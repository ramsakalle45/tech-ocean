## A worked example

```python
import time
import random
from openai import OpenAI, APIError, RateLimitError

client = OpenAI()

def ask(prompt: str, *, model: str = "gpt-4o-mini", attempts: int = 4) -> str:
    for attempt in range(attempts):
        try:
            response = client.chat.completions.create(
                model=model,
                messages=[{"role": "user", "content": prompt}],
                max_tokens=500,
                temperature=0.2,
            )
            return response.choices[0].message.content or ""
        except RateLimitError:
            time.sleep((2 ** attempt) + random.random())
        except APIError as exc:
            if attempt == attempts - 1:
                raise
            time.sleep(1)
    raise RuntimeError("unreachable")
```

Exponential backoff with jitter, and a hard cap on attempts. The jitter matters — without it, every client retries at the same instant.

<Callout type="interview" title="Interview corner">
**How do you keep a chat feature from costing more than it earns?**

Three levers. Use the smallest model that passes your evaluation. Cap output tokens, since output is usually more expensive per token than input. And cache aggressively — for repeated or near-identical prompts, a semantic cache over embeddings often removes a large fraction of calls. Add a per-user budget so one client cannot exhaust the account.
</Callout>

## Quick recap

- Set `max_tokens` on every call. Unbounded output is unbounded cost.
- Retry with exponential backoff and jitter; make retries idempotent.
- Model choice, output length and caching are the three cost levers.
