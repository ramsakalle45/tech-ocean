## What you will learn

- Constrain a model to a JSON schema and parse the result
- Validate output with a schema, and decide what to do when it fails
- Extract structured data from unstructured text
- Design a schema that is easy for a model to fill correctly

## Why it matters

Free-form text is hard to build on. A validated object is a contract you can test, cache, and hand to another service. The parsing step is where the reliability comes from.

## A worked example

```python
from pydantic import BaseModel, Field, ValidationError

class Ticket(BaseModel):
    title: str = Field(description="one line, no punctuation at the end")
    severity: int = Field(ge=1, le=4, description="1 lowest, 4 highest")
    tags: list[str] = Field(default_factory=list)

try:
    ticket = Ticket.model_validate_json(model_output)
except ValidationError as exc:
    logger.warning("model returned invalid data: %s", exc)   # log, then retry or fall back
    raise
```

Constrained decoding makes invalid output unlikely, not impossible. Validate anyway, and decide in advance whether a failure means retry, fall back, or escalate.

<Callout type="interview" title="Interview corner">
**Should you retry when a model returns output that fails schema validation?**

Sometimes. If the failure is a small formatting slip, a retry with the validation error fed back usually succeeds. If the model consistently cannot satisfy the schema, the schema is probably wrong — simplify it, loosen a field, or split the task. Cap the retries, and always have a fallback path so the feature degrades instead of failing.
</Callout>

## Quick recap

- Constrain the decoder with a schema, but still validate the output.
- Keep schemas shallow — every nesting level is another chance to fail.
- Always have a fallback when validation fails.
