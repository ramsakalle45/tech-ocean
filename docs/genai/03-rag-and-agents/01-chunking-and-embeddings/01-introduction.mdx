## Why it matters

Retrieval quality is capped by chunk quality. A chunk that cuts a definition in half, or merges two unrelated sections, will either miss the question or waste context — and no amount of prompt tuning fixes that.

## A worked example

```python
def chunk_by_heading(text: str, *, max_chars: int = 1200) -> list[dict]:
    """Split on markdown headings, then split any oversized section."""
    sections: list[dict] = []
    heading = "Untitled"
    buffer: list[str] = []

    def flush() -> None:
        if not buffer:
            return
        body = "\n".join(buffer).strip()
        if body:
            sections.append({"heading": heading, "text": body})
        buffer.clear()

    for line in text.splitlines():
        if line.startswith("#"):
            flush()
            heading = line.lstrip("#").strip()
        else:
            buffer.append(line)
    flush()

    # split oversized sections on blank lines
    out: list[dict] = []
    for section in sections:
        while len(section["text"]) > max_chars:
            head, _, tail = section["text"].rpartition("\n\n")
            if not head:
                break
            out.append({"heading": section["heading"], "text": head})
            section = {"heading": section["heading"], "text": tail}
        out.append(section)
    return out
```

Splitting on structure keeps a heading with its body. That single field is often more useful for retrieval than the text itself.

<Callout type="interview" title="Interview corner">
**What chunk size should you use?**

There is no universal answer, so treat it as a tunable. Small chunks retrieve precisely but lose context; large chunks carry context but dilute the embedding and waste the context window. Start around a few hundred tokens, and choose against a question set: measure whether the correct document is retrieved, then tune the size and overlap to improve recall without hurting precision.
</Callout>

## Quick recap

- Chunk on structure where you can — headings, paragraphs, sections.
- Keep the heading with its body as metadata.
- Tune chunk size against a question set, not by intuition.
