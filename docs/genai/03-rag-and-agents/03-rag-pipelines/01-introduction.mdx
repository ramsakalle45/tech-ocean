## What you will learn

- Assemble a retrieve-then-generate pipeline with citations
- Use query rewriting and multi-query expansion to improve recall
- Rerank retrieved candidates before they reach the model
- Design an evaluation set for a RAG system

## Why it matters

RAG is the standard way to give a model knowledge it does not have and to make its answers checkable. The pipeline has more failure modes than it has parts, and each one needs its own measurement.

## A worked example

```python
def answer(question: str, *, k: int = 8, top: int = 3) -> Answer:
    queries = [question, *rewrite(question)]

    candidates: dict[str, Chunk] = {}
    for q in queries:
        for chunk in vector_search(q, limit=k):
            candidates[chunk.id] = chunk      # dedupe across queries

    ranked = rerank(question, list(candidates.values()))[:top]

    context = "\n\n".join(
        f"[{i+1}] {c.text}\n(source: {c.source})"
        for i, c in enumerate(ranked)
    )

    result = generate(
        system="Answer using only the numbered sources. "
               "Cite the numbers you used. If the answer is not there, say so.",
        user=f"Question: {question}\n\nSources:\n{context}",
    )
    return Answer(text=result.text, citations=[c.source for c in ranked])
```

The citation instruction plus the numbered context is what makes an answer checkable. Reranking a wider candidate set into a narrow one is usually the biggest quality win.

<Callout type="interview" title="Interview corner">
**Your RAG system returns irrelevant documents. How do you debug it?**

Split the problem in two. First measure retrieval: is the correct document in the retrieved set at all? If not, it is a chunking or embedding problem. If it is there but the answer is wrong, it is a generation problem — the context is fine but the model ignored or was confused by it. Measure both separately, because the fixes are completely different.
</Callout>

## Quick recap

- Measure retrieval quality and generation quality separately.
- Retrieve wide, rerank narrow.
- Always ask for citations, and always give the model a way to say "not found".
