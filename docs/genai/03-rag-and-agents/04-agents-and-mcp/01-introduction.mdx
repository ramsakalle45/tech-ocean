## What you will learn

- Describe the agent loop: plan, act, observe, repeat

- Explain the Model Context Protocol and the problem it solves

## Why it matters

Agents trade predictability for flexibility. That trade is worth it for some tasks and ruinous for others, and the difference is usually about how much the task can vary.

## A worked example

```python
def run_agent(task: str, *, max_steps: int = 12, deadline: float = 120.0) -> Result:
    started = time.monotonic()
    messages = [{"role": "user", "content": task}]

    for step in range(max_steps):
        if time.monotonic() - started > deadline:
            return Result(status="timeout", steps=step)

        calls = llm(messages, tools=TOOLS)          # may request tool calls
        messages += calls.messages

        if not calls.tool_calls:
            return Result(status="done", output=calls.text, steps=step + 1)

        for call in calls.tool_calls:
            result = run_tool(call)                   # authorised, validated, logged
            messages.append(tool_message(call, result))

    return Result(status="max_steps", steps=max_steps)
```

The limits are the point. An unbounded agent loop is an unbounded bill, and a request that is not authorised is a request that should never have been made.

<Callout type="interview" title="Interview corner">
**When is a plain pipeline better than an agent?**

When the steps are known and the order matters. A fixed pipeline is cheaper, faster, reproducible and easy to test. Agents pay off when the sequence of steps genuinely varies with the input — when the model has to decide what to look up, in what order, and when it is done. </Callout>

## Quick recap

- An agent is a loop with a decision at the top and a hard stop at the bottom.
- Use a fixed pipeline whenever the steps are knowable in advance.
- Bound every agent: step limit, time limit, spend limit, and permissions.
