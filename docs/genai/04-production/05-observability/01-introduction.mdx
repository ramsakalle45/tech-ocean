## What you will learn

- Trace a request from prompt to tool calls to final output
- Log what you need to debug a bad answer, without logging private data
- Build dashboards that show quality, not just volume
- Use traces to find where an agent went wrong

## Why it matters

A language-model system fails in ways that logs of status codes will never show. You need to see the prompt, the retrieved context, the tool calls and the final output — linked together, per request.

## A worked example

```python
@trace("rag.answer")
def answer(question: str, user_id: str) -> Answer:
    with span("retrieve") as s:
        chunks = vector_search(question)
        s.set_attribute("chunk_count", len(chunks))
        s.set_attribute("chunk_ids", [c.id for c in chunks])

    with span("generate") as s:
        result = generate(context=chunks, question=question)
        s.set_attribute("input_tokens", result.usage.input)
        s.set_attribute("output_tokens", result.usage.output)
        s.set_attribute("citations", result.citations)

    log.info("rag.answer", extra={
        "user_id": user_id,
        "question_hash": hash_text(question),   # not the question itself
        "top_score": chunks[0].score if chunks else None,
    })
    return result
```

Hash or redact user content in logs, and keep the trace. You want to debug a bad answer next week without holding everyone’s personal data.

<Callout type="interview" title="Interview corner">
**A user says the assistant gave a wrong answer. What do you need to investigate?**

The trace for that request: the exact prompt, the documents retrieved and their scores, the tool calls made and their arguments, the model’s raw output, and the final response. Without the retrieval step you cannot tell a retrieval failure from a generation failure, and those have completely different fixes. This is why the trace has to exist before the complaint does.
</Callout>

## Quick recap

- Trace every request end to end, with the retrieval step included.
- Redact user content in logs; keep the structure.
- Dashboards should show quality signals, not only request counts.
