## What you will learn

- Write a function with a clear contract: what it takes, what it returns, what it raises
- Choose between positional, keyword, default and keyword-only arguments deliberately
- Explain closures without hand-waving, and know when a lambda is the wrong tool
- Decide what belongs in a return value and what belongs in a side effect

## Why it matters

Functions are the smallest unit of a program you can test on its own. A program that is one long script cannot be unit tested, reused, or reasoned about.

## A worked example

```python
def normalise(name: str, *, upper: bool = False) -> str:
    """Return the display form of a name."""
    name = name.strip()
    return name.upper() if upper else name.title()

normalise("  ada lovelace ")           # 'Ada Lovelace'
normalise("ada lovelace", upper=True)  # 'ADA LOVELACE'
```

The `*` makes `upper` keyword-only. It reads well and it stops a positional call from silently meaning something else.

<Callout type="interview" title="Interview corner">
**Why is a mutable default argument a classic Python bug?**

The default is evaluated once, when the `def` runs, not on each call. `def f(items=[])` creates one list that is shared by every call that omits `items`, and it survives between calls. Use `None` as the sentinel and build the real default inside the function.
</Callout>

## Quick recap

- A function should do one thing and say so in its name.
- Return values, not prints — printing makes a function impossible to compose or test.
- Never use a mutable default. Use `None` and construct inside.
