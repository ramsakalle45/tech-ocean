## What you will learn

- Pick the right container for a job instead of defaulting to list
- Use dict and set operations to make code shorter and faster
- Write comprehensions that read like a sentence
- Know when a comprehension is costing more than it saves

## Why it matters

The container you choose determines the complexity of everything you do with it. `item in list` is O(n); `item in set` is O(1). That difference shows up in every loop you write.

## A worked example

```python
words = ["Apple", "apple", "banana", "Banana"]

counts = {}
for w in words:
    key = w.lower()
    counts[key] = counts.get(key, 0) + 1
# {'apple': 2, 'banana': 2}

unique = {w.lower() for w in words}      # set
pairs = {w.lower(): len(w) for w in words}  # dict
```

Reach for `collections.Counter` before hand-rolling the counting loop — it is faster and clearer.

<Callout type="interview" title="Interview corner">
**When is a list faster than a set, and when is a set faster than a list?**

For a small number of items, a list can be faster because it has less overhead and better cache locality. Once you are repeatedly testing membership over a large collection, the set wins by a large margin, because lookup drops from O(n) to O(1). The crossover is usually around a dozen elements.
</Callout>

## Quick recap

- list: ordered, mutable, duplicates allowed. tuple: ordered, immutable.
- dict: keyed lookup. set: membership, uniqueness, and set algebra.
- Prefer comprehensions for building a collection from another.
