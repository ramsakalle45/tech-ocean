## What you will learn

- Write a decorator that preserves the wrapped function’s metadata and signature
- Explain what a closure captures and when that capture goes stale
- Use `yield` to write a generator, and `yield from` to delegate one
- Choose between a generator and a list for a large result set

## Why it matters

Decorators are how Python adds behaviour without editing the original code — timing, caching, retries, authorisation. Generators are how Python handles sequences too large to hold in memory. Both show up constantly in real code.

## A worked example

```python
import functools
import time

def timed(fn):
    @functools.wraps(fn)          # keeps __name__, __doc__ and the signature
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__}: {time.perf_counter() - start:.3f}s")
    return wrapper

@timed
def slow(n):
    return sum(range(n))
```

Without `functools.wraps`, the decorated function reports the wrong name and docstring — which quietly breaks introspection, logging and some test frameworks.

<Callout type="interview" title="Interview corner">
**What is the late-binding closure bug?**

A closure captures a variable by reference, not by value. If you build a list of functions in a loop and each one refers to the loop variable, they all see the *final* value of that variable, not the value at the time they were created. The fix is to bind the current value explicitly, for example with a default argument or a factory function.
</Callout>

## Quick recap

- A decorator is a function that takes a function and returns a function.
- Always use `functools.wraps` on the wrapper.
- A generator is a function that returns a lazy iterator; `yield` pauses it.
