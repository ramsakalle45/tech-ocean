## What you will learn

- Write a comprehension for each of list, dict, set and generator
- Know when a comprehension should be a plain loop
- Annotate functions so a type checker catches real mistakes
- Use `TypedDict`, `Protocol` and generics where they pay off

## Why it matters

Comprehensions turn a build-then-fill loop into one expression, which reads better and is usually faster. Type hints cost a few minutes and catch a class of bugs that would otherwise only appear in production.

## A worked example

```python
from collections.abc import Iterable, Iterator
from typing import TypeVar

T = TypeVar("T")

def unique(items: Iterable[T]) -> Iterator[T]:
    seen: set[T] = set()
    for item in items:
        if item not in seen:
            seen.add(item)
            yield item

numbers = unique([1, 2, 2, 3, 3, 3])   # a generator, not a list
```

A generator expression is the lazy cousin of a list comprehension: same syntax, but nothing is built until you iterate it.

<Callout type="interview" title="Interview corner">
**When is a plain loop better than a comprehension?**

When the loop does more than produce a value — when it has several statements, when it needs to break out early, or when the intermediate value is not a collection at all. A comprehension that needs a nested `if` to stay readable is usually a loop in disguise.
</Callout>

## Quick recap

- Comprehensions build a collection; generator expressions build an iterator.
- Annotate the public surface of a module, not every local.
- `Optional[X]` means `X | None` — never leave that ambiguous at a call site.
