## A worked example

```python
def trap():
    items = []
    for i in range(3):
        items.append(lambda: i)
    return [f() for f in items]      # [2, 2, 2] — late binding

def fixed():
    items = []
    for i in range(3):
        items.append(lambda i=i: i)
    return [f() for f in items]      # [0, 1, 2]
```

Both functions look identical. The difference is one keyword argument, and it is the difference between a bug and a feature.

<Callout type="interview" title="Interview corner">
**What is the difference between `is` and `==`?**

`==` asks whether two objects are equal by value — and that is defined per type, so a custom class can decide what equality means. `is` asks whether two names point at the same object. Small integers and short strings are interned, so `x is y` can be true for equal values; that is an implementation detail, not a guarantee you should rely on.
</Callout>

## Quick recap

- Interning makes `is` unreliable for value comparison.
- Closures bind late unless you bind explicitly.
- Know the cost of each operation you quote.
