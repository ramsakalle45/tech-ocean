## A worked example

```python
# Round One, Problem 1 — see the module page for the full statement.
#
# "Given a list of integers, return the sum of the two largest
#  that are not adjacent in the original list."
#
# Time limit: 20 minutes, including tests.

def two_largest_non_adjacent(nums: list[int]) -> int:
    if not nums:
        raise ValueError("need at least two values")
    if len(nums) == 2:
        return sum(nums)

    prev_two, prev_one = 0, 0
    for index, value in enumerate(nums):
        if index < 2:
            best = value if index == 0 else nums[0] + value
        else:
            best = max(prev_one, prev_two + value)
        prev_two, prev_one = prev_one, best
    return prev_one
```

The trick is to define the state clearly: "the best sum using the first i elements". Naming the state is most of dynamic programming.

<Callout type="interview" title="Interview corner">
**You finished a problem but your tests did not cover an edge case. What now?**

Say it out loud. Interviewers are assessing your process, and a candidate who volunteers "let me check the empty input" is demonstrating exactly the habit they want. Then add the case and see whether your solution still holds — if it does not, that is a good outcome too: you found a bug before they did.
</Callout>
