## What you will learn

- Select columns in a deliberate order, with aliases that read well in output
- Filter with `WHERE` and understand why it runs before aggregation
- Handle `NULL` correctly instead of assuming it behaves like a value
- Read a `SELECT` statement and predict how many rows come back

## A worked example

```sql
SELECT
    o.id                AS order_id,
    c.name              AS customer,
    o.total_cents / 100.0 AS total
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id
WHERE o.status = 'shipped'
  AND o.placed_at >= DATE '2026-01-01'
  AND o.total_cents IS NOT NULL
ORDER BY o.placed_at DESC
LIMIT 50;
```

Alias columns in the `SELECT` list, not in the `WHERE`. You cannot use an alias in `WHERE` in standard SQL — only in `ORDER BY`.

<Callout type="interview" title="Interview corner">
**Why does `WHERE column = NULL` return no rows?**

Because `NULL` means "unknown", not "no value". Every comparison with `NULL` evaluates to unknown, and `WHERE` keeps a row only when the condition is definitively true. Use `IS NULL` and `IS NOT NULL` instead.
</Callout>

## Quick recap

- Logical order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY.
- `WHERE` filters rows; `HAVING` filters groups.
- Test for null with `IS NULL`, never `= NULL`.
