## What you will learn

- Create a table with sensible types and constraints
- Choose between common column types and know what each stores
- Insert, update and delete rows safely
- Make a schema change without losing data

## Why it matters

The schema is the contract every query depends on. A column typed as text when it should be a number, or a timestamp with no timezone, causes bugs that surface months later.

## A worked example

```sql
CREATE TABLE orders (
    id           BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id  BIGINT      NOT NULL REFERENCES customers (id),
    total_cents  BIGINT      NOT NULL CHECK (total_cents >= 0),
    currency     CHAR(3)     NOT NULL DEFAULT 'GBP',
    placed_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    metadata     JSONB
);

CREATE INDEX orders_customer_placed_idx
    ON orders (customer_id, placed_at DESC);
```

Money as an integer count of minor units, and timestamps with a timezone. Both decisions save you later.

<Callout type="interview" title="Interview corner">
**Why store money as an integer instead of a float?**

Binary floating point cannot represent most decimal fractions exactly, so `0.1 + 0.2` is not `0.3`. For money, store the smallest unit as an integer — 1050 pence — and format only at the edges. Alternatively use a fixed-precision decimal type, but never a float.
</Callout>

## Quick recap

- Use `TIMESTAMPTZ`, not `TIMESTAMP`, for real-world time.
- Store money in minor units as an integer.
- Add columns as nullable, backfill, then add the constraint.
