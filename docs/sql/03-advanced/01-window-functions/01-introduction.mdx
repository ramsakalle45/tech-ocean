## Why it matters

A window function gives you a per-row calculation over a set of rows, while keeping every row. That is exactly what "running total" or "top three per group" needs, and what a group-by aggregate cannot give you.

## A worked example

```sql
SELECT
    order_id,
    customer_id,
    placed_at,
    total_cents,
    SUM(total_cents) OVER (
        PARTITION BY customer_id
        ORDER BY placed_at
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total_cents,
    ROW_NUMBER() OVER (
        PARTITION BY customer_id
        ORDER BY placed_at DESC
    ) AS recency_rank
FROM orders;
```

The frame clause is the part people forget. Without `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`, the default frame is the whole partition and the "running" total is wrong.

<Callout type="interview" title="Interview corner">
**What is the difference between `RANK` and `DENSE_RANK`?**

With ties, `RANK` skips the next value — ranks 1, 1, 3 — while `DENSE_RANK` does not — 1, 1, 2. `ROW_NUMBER` breaks ties arbitrarily, so it is not stable unless the ordering is fully deterministic. If you need a stable top-N per group, order by a unique column as the tiebreaker.
</Callout>

## Quick recap

- Windows compute across rows; aggregation collapses them.
- Always state the frame clause when you mean "running total".
- Add a unique tiebreaker to any ranking you intend to page through.
