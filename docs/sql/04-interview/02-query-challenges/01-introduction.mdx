## A worked example

```sql
-- Challenge: "customers who have ordered in every month of 2025".
-- The trap: writing this as a plain join and counting rows.
WITH months AS (
    SELECT generate_series(1, 12) AS month
),
buyers AS (
    SELECT DISTINCT customer_id, EXTRACT(MONTH FROM placed_at)::int AS month
    FROM orders
    WHERE placed_at >= DATE '2025-01-01'
      AND placed_at <  DATE '2026-01-01'
)
SELECT o.customer_id
FROM orders AS o
GROUP BY o.customer_id
HAVING COUNT(DISTINCT EXTRACT(MONTH FROM o.placed_at)) = 12;
```

The naive version counts order rows, not distinct months. Counting distinct values is almost always the right move in a "in every period" question.

<Callout type="interview" title="Interview corner">
**What is the most common mistake in a "count of distinct X per group" question?**

Counting rows instead of distinct values, because a group can contain several rows for the same X. `COUNT(*)` and `COUNT(DISTINCT x)` differ exactly when there are duplicates — and the question usually means the latter.
</Callout>

## Quick recap

- Read the question twice: what is one row of the answer?
- Watch for the difference between counting rows and counting distinct values.
- Check the empty and single-row cases.
