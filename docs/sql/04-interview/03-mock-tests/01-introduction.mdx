## A worked example

```sql
-- Round One, Question 1
-- "For each month, what percentage of orders were refunded?"
WITH months AS (
    SELECT generate_series(
        DATE '2025-01-01', DATE '2025-12-01', INTERVAL '1 month'
    ) AS month
),
totals AS (
    SELECT
        date_trunc('month', placed_at) AS month,
        COUNT(*) AS total,
        COUNT(*) FILTER (WHERE status = 'refunded') AS refunded
    FROM orders
    WHERE placed_at >= DATE '2025-01-01'
      AND placed_at <  DATE '2026-01-01'
    GROUP BY 1
)
SELECT
    m.month,
    COALESCE(t.refunded, 0) AS refunded,
    COALESCE(t.total, 0) AS total,
    ROUND(100.0 * COALESCE(t.refunded, 0) / NULLIF(t.total, 0), 1) AS pct_refunded
FROM months AS m
LEFT JOIN totals AS t ON t.month = m.month
ORDER BY m.month;
```

Generating the month series and left-joining it is what makes months with no orders appear as zero rather than vanishing.

<Callout type="interview" title="Interview corner">
**Your query returns one row when the interviewer expected five. What is the first thing to check?**

The grain. Either the join collapsed rows — a missing `GROUP BY` column, or a join to a table that fans out and then got aggregated differently — or the filter is too aggressive. Add a `COUNT(*)` and look at the row count at each stage of the query.
</Callout>

## Quick recap

- Name the grain of the answer before writing the query.
- Build up in steps and check the count at each one.
- A missing month is a data point — generate the series explicitly.
