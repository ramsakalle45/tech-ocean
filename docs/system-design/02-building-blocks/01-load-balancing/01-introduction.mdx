## A worked example

```text
Round-robin is wrong when instances are not identical:

  instance A: 100ms per request
  instance B: 900ms per request

  Round-robin sends half the traffic to the slow one, and every
  user behind it waits. Least-connections does better here, but
  the real fix is not a smarter algorithm — it is to fix or
  remove the slow instance.

  Weighted balancing helps when you are deliberately running
  different tiers: 90% of traffic to the standard fleet, 10% to
  a canary, so you can compare them under real load.
```

A load balancer distributes work; it does not repair a bad instance. Health checking is what removes it from rotation.

<Callout type="interview" title="Interview corner">
**How do you roll out a new version with no downtime?**

Deploy the new version alongside the old, have the balancer send a small percentage of traffic to it, and watch error rate and latency for both groups. Increase the percentage in stages, and keep the old version running and able to take traffic back. The parts that make it work are the health check removing bad instances, and a connection drain so in-flight requests finish rather than being cut.
</Callout>

## Quick recap

- Match the algorithm to the workload; fix slow instances, do not route around them.
- Health checks must be able to distinguish "busy" from "broken".
- Canary with weighted routing beats all-at-once deploys.
