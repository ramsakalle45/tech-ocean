## What you will learn

- Choose between SQL and NoSQL from the access patterns, not from fashion
- Normalise or denormalise deliberately
- Shard by a key and handle the routing that implies
- Know what replication gives you and what it does not

## Why it matters

The database is the part of the system that holds the truth, and it is the part with the fewest easy escapes. Choosing a storage model from your access patterns is the decision everything else builds on.

## A worked example

```text
Sharding by tenant_id (one database per tenant):

  + Simple routing: shard = hash(tenant_id) % N
  + One tenant's data is on one shard — no cross-shard queries
  + Easy per-tenant backup, restore and deletion (GDPR)
  - A huge tenant hot-shards everything
  - Adding shards needs a resharding of every tenant

Sharding by user_id (one database per hash range):

  + Even load, no big tenants
  + Resharding is a range split, not a full move
  - Queries spanning users need fan-out
  - "All messages for this team" is now a scatter-gather

Neither is universally right. The choice is driven by your
dominant access pattern — so write that down before sharding.
```

Every sharding decision creates queries that will no longer be cheap. Name the query that will hurt before you commit.

<Callout type="interview" title="Interview corner">
**When would you use a NoSQL store instead of a relational database?**

When the access patterns are known, stable, and simple — a single key lookup, or a range scan over one dimension — and the volume or write rate genuinely exceeds what a well-indexed relational database handles. A document store that holds a whole entity and is always read whole is a good fit. If the data is relational, the queries vary, and you need transactions across rows, relational is still the better answer, whatever the throughput number says.
</Callout>

## Quick recap

- Choose the store from access patterns, not from trends.
- Replication gives you availability and read scale; it does not remove the write bottleneck.
- Name the query that will hurt before you shard.
