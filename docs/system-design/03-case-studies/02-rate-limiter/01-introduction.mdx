## What you will learn

- Implement token bucket and sliding window, and know when each fits
- Choose the scope: per user, per IP, per API key, or global
- Distribute a limiter across instances
- Return a correct response when the limit is hit

## Why it matters

Rate limiting is a small component with an outsized effect: it protects everything downstream, and getting the algorithm right matters more than the storage.

## A worked example

```python
class TokenBucket:
    """Token bucket: allows bursts, smooths the average rate."""

    def __init__(self, *, rate_per_second: float, burst: int):
        self.rate = rate_per_second
        self.burst = burst
        self.tokens = float(burst)
        self.updated_at = time.monotonic()

    def allow(self, *, cost: int = 1) -> bool:
        now = time.monotonic()
        self.tokens = min(
            self.burst,
            self.tokens + (now - self.updated_at) * self.rate,
        )
        self.updated_at = now

        if self.tokens >= cost:
            self.tokens -= cost
            return True
        return False
```

Token bucket permits a burst up to the bucket size, then enforces the average rate. That is usually what an API wants: a short spike is fine, a sustained flood is not.

<Callout type="interview" title="Interview corner">
**How do you rate limit across 100 API instances?**

Either centralise the counter in a shared store — Redis with an atomic script — which gives an exact global limit at the cost of a network hop on every request, or run a local limiter on each instance with the limit divided by 100, which is fast and approximate but allows the true rate to exceed the limit by up to the number of instances during a burst. Many systems do both: a loose local limit to shed obvious abuse, and a strict central limit for the real quota.
</Callout>

## Quick recap

- Token bucket for bursty traffic; sliding window for strict fairness.
- Decide the key before the algorithm: per user, per IP, or per key.
- Always tell the client what to do — 429 plus `Retry-After`.
